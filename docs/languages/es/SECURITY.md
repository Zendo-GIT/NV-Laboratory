# Seguridad

Esta política cubre los paquetes de aplicaciones NV Tools y este centro de distribución. El mantenedor prioriza los informes que afectan a la última versión publicada de cada herramienta. Los candidatos preparados no son una versión estable compatible anunciada. No se promete ningún plazo de respuesta ni certificación de seguridad.

<a id="report-privately"></a>
## Informar en privado

Para vulnerabilidades, comportamiento elevado inseguro, cambios destructivos no deseados o exposición de datos confidenciales, utilice la función **Seguridad → Report a vulnerability** del repositorio **cuando esté habilitada**: [informe privado](https://github.com/Zendo-GIT/NV-Laboratory/security/advisories/new).

**Configuración inicial:** el responsable del mantenimiento debe habilitar los informes de vulnerabilidad privados después de crear el repositorio público. Este archivo no lo habilita y no se afirma que exista ningún buzón o canal privado antes de esa fecha.

Si el botón no está disponible, abra un problema público que contenga únicamente: "Necesito un canal de contacto privado para un informe de seguridad relacionado con [herramienta/versión]". No incluya detalles del exploit, credenciales, rutas afectadas, registros o archivos adjuntos. Espere a que el mantenedor proporcione un canal privado antes de compartirlos.

En el informe privado, incluya la herramienta/versión y el hash, Windows/GPU/versiones del controlador, impacto, reproducción mínima segura y si se necesita recuperación. Redactar secretos y datos personales; conservar los archivos de recuperación locales. No cargue controladores propietarios ni archivos DLL de juegos. Coordinar la divulgación con el mantenedor; un parche/lanzamiento requiere revisión y no es automático.


[GitHub documentación de informes privados](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
