# Contribuindo

NV Laboratory é mantido por 禅堂 Zendo (RevoluSound Team). O mantenedor decide o que é aceito e liberado. Abrir um Issue ou Pull Request não significa que uma contribuição seja aceita ou autorizada para distribuição.

Use o formulário de bug ou recurso e identifique o programa/versão. Pesquise primeiro os problemas existentes. Discuta mudanças substanciais antes de preparar uma grande contribuição. Para questões de segurança, siga [SECURITY.md](SECURITY.md).

Este hub público contém documentação, avisos, metadados de lançamento e validação de repositório. A fonte e os testes do aplicativo são mantidos de forma privada. Não envie código descompilado, fonte privada, credenciais, perfis de usuário ou cargas executáveis.

Os PRs de documentação devem manter as contrapartes de 34 idiomas e a navegação alinhadas, preservar nomes de comandos/arquivos/produtos e descrever o comportamento real. As novas capturas de tela devem ser suas, identificadas pela versão e livres de dados pessoais; os dados sintéticos devem ser rotulados. Forneça a procedência e a permissão para cada novo ativo de terceiros.

Use UTF-8, LF, Markdown legível e pequenas alterações focadas. O validador Python utiliza apenas a biblioteca padrão. Combine seu estilo existente, evite dependências desnecessárias e execute:

```text
python tools/validate_repository.py
```

Para alterações de metadados de lançamento, inclua a versão/tag exata, tamanhos de arquivo e SHA-256 dos binários auditados e mantenha as páginas de download alinhadas. As alterações no aplicativo exigem construção/testes privados apropriados ao comportamento afetado; uma verificação de documentação não é um teste de aplicação. Nunca invente resultados ou ganhos históricos de testes.

Ao contribuir com material original do hub, você concorda com o escopo da licença MIT em [LICENÇA](../../../LICENSE). Guarde avisos de terceiros e identifique suas alterações; não substitua uma licença upstream. A aceitação e a publicação continuam sendo decisões do mantenedor.
