# Segurança

Esta política cobre pacotes de aplicativos NV Tools e este hub de distribuição. O mantenedor prioriza relatórios que afetam a última versão publicada de cada ferramenta. Os candidatos preparados não são uma versão estável com suporte anunciada. Nenhum prazo de resposta ou certificação de segurança é prometido.

<a id="report-privately"></a>
## Denunciar em particular

Para vulnerabilidades, comportamento elevado inseguro, alterações destrutivas não intencionais ou exposição de dados confidenciais, use o recurso **Segurança → Report a vulnerability** do repositório **quando estiver ativado**: [relatório privado](https://github.com/Zendo-GIT/NV-Laboratory/security/advisories/new).

**Configuração inicial:** o mantenedor deve habilitar o relatório de vulnerabilidade privada após criar o repositório público. Este arquivo não o habilita e nenhuma caixa de correio ou canal privado existe antes disso.

Caso o botão não esteja disponível, abra um Issue público contendo apenas: “Preciso de um canal de contato privado para um relatório de segurança referente a [ferramenta/versão].” Não inclua detalhes de exploração, credenciais, caminhos afetados, logs ou anexos. Espere que o mantenedor forneça um canal privado antes de compartilhá-los.

No relatório privado, inclua ferramenta/versão e hash, versões Windows/GPU/driver, impacto, reprodução segura mínima e se a recuperação é necessária. Editar segredos e dados pessoais; preservar arquivos de recuperação locais. Não carregue drivers proprietários ou DLLs de jogos. Coordenar a divulgação com o mantenedor; um patch/lançamento requer revisão e não é automático.


[Documentação de relatórios privados GitHub](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
