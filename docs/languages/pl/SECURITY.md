# Bezpieczeństwo

Niniejsza polityka dotyczy pakietów aplikacji NV Tools i tego centrum dystrybucyjnego. Opiekun nadaje priorytet raportom wpływającym na najnowszą opublikowaną wersję każdego narzędzia. Przygotowane programy kandydujące nie są ogłoszoną, wspieraną wersją stabilną. Nie gwarantuje się terminu odpowiedzi ani certyfikatu bezpieczeństwa.

<a id="report-privately"></a>
## Zgłoś się prywatnie

W przypadku luk w zabezpieczeniach, niebezpiecznych zachowań o podwyższonym poziomie, niezamierzonych destrukcyjnych zmian lub ujawnienia wrażliwych danych, użyj funkcji repozytorium **Bezpieczeństwo → Report a vulnerability** **jeśli jest włączona**: [raport prywatny](https://github.com/Zendo-GIT/NV-Laboratory/security/advisories/new).

**Konfiguracja wstępna:** opiekun musi włączyć raportowanie prywatnych luk w zabezpieczeniach po utworzeniu publicznego repozytorium. Ten plik tego nie umożliwia i nie twierdzi się, że wcześniej istniała żadna skrzynka pocztowa ani kanał prywatny.

Jeśli przycisk jest niedostępny, otwórz publiczne wydanie zawierające tylko: „Potrzebuję prywatnego kanału kontaktowego, aby uzyskać raport bezpieczeństwa dotyczący [narzędzia/wersji]”. Nie dołączaj szczegółów exploitów, danych uwierzytelniających, ścieżek, dzienników ani załączników, których to dotyczy. Poczekaj, aż opiekun udostępni kanał prywatny, zanim go udostępnisz.

W prywatnym raporcie uwzględnij wersję narzędzia/wersję i skrót, wersje Windows/GPU/sterownika, wpływ, minimalną bezpieczną reprodukcję oraz informację, czy potrzebne jest odzyskanie. Redaguj tajemnice i dane osobowe; zachowaj lokalne pliki odzyskiwania. Nie przesyłaj zastrzeżonych plików DLL sterowników ani gier. Koordynuj ujawnianie informacji z opiekunem; łatka/wydanie wymaga sprawdzenia i nie jest automatyczne.


[GitHub prywatna dokumentacja raportowania](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
