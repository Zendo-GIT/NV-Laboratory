# کمک کردن

NV Laboratory توسط 禅堂 Zendo (RevoluSound Team) نگهداری می شود. نگهدار تصمیم می گیرد که چه چیزی پذیرفته و آزاد شود. باز کردن یک موضوع یا درخواست کششی به این معنی نیست که مشارکت پذیرفته شده یا مجاز به توزیع است.

از فرم اشکال یا ویژگی استفاده کنید و برنامه/نسخه را شناسایی کنید. ابتدا مسائل موجود را جستجو کنید. قبل از تهیه یک مشارکت بزرگ در مورد تغییرات اساسی بحث کنید. برای مسائل امنیتی، [SECURITY.md](SECURITY.md) را دنبال کنید.

این مرکز عمومی حاوی اسناد، اعلامیه‌ها، ابرداده‌های انتشار و اعتبارسنجی مخزن است. منبع برنامه و تست ها به صورت خصوصی نگهداری می شوند. کد دکامپایل شده، منبع خصوصی، اعتبارنامه، نمایه های کاربر یا بارهای اجرایی را ارسال نکنید.

PR اسناد باید 34 زبان مشابه و ناوبری را در یک راستا نگه دارند، نام فرمان/فایل/محصول را حفظ کنند و رفتار واقعی را توصیف کنند. اسکرین شات های جدید باید متعلق به شما، شناسایی شده بر اساس نسخه و بدون جزئیات شخصی باشد. داده های مصنوعی باید برچسب گذاری شوند. منشأ و مجوز هر دارایی شخص ثالث جدید را ارائه دهید.

از UTF-8، LF، Markdown قابل خواندن و تغییرات متمرکز کوچک استفاده کنید. اعتبار سنجی Python فقط از کتابخانه استاندارد استفاده می کند. سبک موجود آن را مطابقت دهید، از وابستگی های غیر ضروری اجتناب کنید و اجرا کنید:

```text
python tools/validate_repository.py
```

برای تغییرات فراداده انتشار، نسخه/برچسب دقیق، اندازه فایل و SHA-256 را از باینری های ممیزی شده درج کنید و صفحات دانلود را هم تراز نگه دارید. تغییرات برنامه نیاز به ساخت/تست های خصوصی متناسب با رفتار آسیب دیده دارد. بررسی مدارک یک آزمون کاربردی نیست. هرگز نتایج یا دستاوردهای آزمون تاریخی را اختراع نکنید.

با ارائه مطالب اصلی مرکز، با مجوز MIT محدوده آن در [مجوز](../../../LICENSE) موافقت می کنید. اعلامیه های شخص ثالث را نگه دارید و تغییرات خود را شناسایی کنید. مجوز بالادستی را جایگزین نکنید. پذیرش و انتشار همچنان تصمیمات نگهدارنده است.
