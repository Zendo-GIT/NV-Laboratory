# ਪ੍ਰਕਾਸ਼ਨ ਅਤੇ ਰੀਲੀਜ਼

ਜਨਤਕ ਭੰਡਾਰ **Zendo-GIT/NV-Labboratory** ਹੈ। ਦਸਤਾਵੇਜ਼ੀ ਤਬਦੀਲੀਆਂ ਦੀ **GitHub Desktop** ਦੇ ਨਾਲ ਮੇਨਟੇਨਰ ਦੁਆਰਾ ਸਮੀਖਿਆ ਕੀਤੀ ਜਾਂਦੀ ਹੈ, ਪ੍ਰਤੀਬੱਧ ਅਤੇ ਅੱਗੇ ਵਧਾਇਆ ਜਾਂਦਾ ਹੈ। ਇੱਕ ਸਥਾਨਕ ਕਮਿਟ ਫਾਈਲਾਂ ਨੂੰ ਅੱਪਲੋਡ ਨਹੀਂ ਕਰਦਾ ਹੈ। ਬਾਈਨਰੀ ਪੈਕੇਜ ਵੱਖਰੇ GitHub ਰੀਲੀਜ਼ ਸੰਪਤੀਆਂ ਹਨ; ਉਹ ਕਦੇ ਵੀ ਗਿੱਟ ਪਰਿਵਰਤਨ ਸੂਚੀ ਵਿੱਚ ਸ਼ਾਮਲ ਨਹੀਂ ਹੁੰਦੇ ਹਨ।

<a id="documentation-updates"></a>
## ਦਸਤਾਵੇਜ਼ੀ ਅੱਪਡੇਟ

1. GitHub Desktop ਵਿੱਚ **NV-Laboratory** ਫੋਲਡਰ ਖੋਲ੍ਹੋ।
2. ਦਸਤਾਵੇਜ਼ਾਂ, ਨੋਟਿਸਾਂ, ਚਿੱਤਰਾਂ, JSON ਮੈਟਾਡੇਟਾ ਅਤੇ ਦਸਤਾਵੇਜ਼ ਪ੍ਰਮਾਣਕ ਦੀ ਸਮੀਖਿਆ ਕਰੋ।
3. ਉਸ ਫੋਲਡਰ ਤੋਂ `python tools/validate_repository.py` ਚਲਾਓ।
4. ਸਮੀਖਿਆ ਕੀਤੀਆਂ ਤਬਦੀਲੀਆਂ ਨੂੰ ਕਮਿਟ ਕਰੋ, ਫਿਰ **Push origin** ਦੀ ਵਰਤੋਂ ਕਰੋ। ਕਾਰਵਾਈਆਂ ਦੇ ਨਤੀਜੇ ਦੀ ਜਾਂਚ ਕਰੋ।
5. ਜਨਤਕ ਲੇਖਕ ਦੀ ਪਛਾਣ **禅堂 Zendo (RevoluSound Team)** ਅਤੇ ਖਾਤੇ ਦਾ GitHub `noreply` ਪਤਾ ਰੱਖੋ।

ਕਦੇ ਵੀ ਪੇਰੈਂਟ ਡਿਵੈਲਪਮੈਂਟ ਵਰਕਸਪੇਸ, ਪ੍ਰਾਈਵੇਟ ਆਡਿਟ ਡਾਇਰੈਕਟਰੀ ਜਾਂ ਬਾਈਨਰੀ ਅਟੈਚਮੈਂਟ ਡਾਇਰੈਕਟਰੀ ਦੀ ਚੋਣ ਨਾ ਕਰੋ। [ਈਮੇਲ ਗੋਪਨੀਯਤਾ ਦੀ ਵਚਨਬੱਧਤਾ ਕਰੋ](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address)।

## ਸੁਤੰਤਰ ਐਪਲੀਕੇਸ਼ਨ ਰੀਲੀਜ਼

| ਟੂਲ | ਟੈਗ ਕਰੋ | ਸੰਸਕਰਣ ਨੀਤੀ |
| --- | --- | --- |
| NVIDIA Profile Inspector – NV Tools Fork | nvpi-v3.0.2.3 | ਮੌਜੂਦਾ ਚਾਰ-ਭਾਗ ਐਪਲੀਕੇਸ਼ਨ ਸੰਸਕਰਣ; ਸੈੱਟਅੱਪ ਰੀਵਿਜ਼ਨ 2 ਦਾ ਆਪਣਾ ਫਾਈਲ ਨਾਂ ਹੈ |
| NVDriverForge | nvdriverforge-v0.1.4 | ਮੌਜੂਦਾ 0.x ਸਕੀਮ; ਵਰਜਨਡ ਅੱਪਡੇਟ ਪੁਰਾਣੇ ਪੈਕੇਜਾਂ ਨੂੰ ਸੁਰੱਖਿਅਤ ਰੱਖਦੇ ਹਨ |
| NVMFG Unlock40 | nvmfg-unlock40-v0.2.3 | ਐਪਲੀਕੇਸ਼ਨ ਸੰਸਕਰਣ 0.2.3; ਜਨਤਕ 0.1.1 ਤੋਂ ਸੰਚਤ ਤਬਦੀਲੀਆਂ |
| NVRasterPulse | nvrasterpulse-v0.2 | ਮੌਜੂਦਾ ਦੋ-ਭਾਗ ਵਾਲਾ ਸੰਸਕਰਣ |

ਮੇਨਟੇਨਰ ਸਿੱਧੇ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰ ਸਕਦਾ ਹੈ ਜਾਂ ਕਿਸੇ ਸਹਾਇਕ ਨੂੰ ਆਡਿਟ ਕੀਤੀਆਂ ਸੰਪਤੀਆਂ ਨੂੰ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰਨ ਲਈ ਅਧਿਕਾਰਤ ਕਰ ਸਕਦਾ ਹੈ। ਪ੍ਰਕਾਸ਼ਨ ਸਪਸ਼ਟ ਹੈ; ਕੋਈ ਵੀ ਵਰਕਫਲੋ ਹਰੇਕ ਵਚਨਬੱਧਤਾ 'ਤੇ ਰੀਲੀਜ਼ ਨਹੀਂ ਬਣਾਉਂਦਾ.

1. ਮੌਜੂਦਾ ਪੂਰਵ-ਪ੍ਰਕਾਸ਼ਨ ਰਿਪੋਰਟ, ਬਾਈਨਰੀਆਂ ਦੇ ਸਰੋਤ, ਲਾਇਸੰਸ ਅਤੇ SHA-256 ਮੁੱਲਾਂ ਦੀ ਸਮੀਖਿਆ ਕਰੋ।
2. ਸਮੀਖਿਆ ਕੀਤੀ ਹੱਬ ਪ੍ਰਤੀਬੱਧਤਾ ਨੂੰ ਨਿਸ਼ਾਨਾ ਬਣਾਉਂਦੇ ਹੋਏ, ਟੂਲ ਦੇ ਟੈਗ ਲਈ ਇੱਕ ਡਰਾਫਟ ਬਣਾਓ। ਤਿਆਰ ਕੀਤੇ ਸੰਸਕਰਣ-ਵਿਸ਼ੇਸ਼ ਰੀਲੀਜ਼ ਨੋਟਸ ਨੂੰ ਸ਼ਾਮਲ ਕਰੋ।
3. ਸਿਰਫ਼ ਉਸ ਸੰਸਕਰਣ ਦੇ ਸੈੱਟਅੱਪ/ਪੋਰਟੇਬਲ ਸੰਪਤੀਆਂ, `Licenses-and-Credits.zip` ਅਤੇ `SHA256SUMS.txt` ਨੂੰ ਨੱਥੀ ਕਰੋ।
4. ਅਨੁਕੂਲਤਾ, ਸਥਾਪਨਾ, ਨਿਰਭਰਤਾ, ਤਬਦੀਲੀਆਂ ਅਤੇ ਜਾਣੀਆਂ ਗਈਆਂ ਸੀਮਾਵਾਂ ਦੀ ਜਾਂਚ ਕਰੋ। RTSS ਨੂੰ NVRasterPulse ਲਈ ਪ੍ਰਮੁੱਖ ਰੱਖੋ।
5. ਪ੍ਰਕਾਸ਼ਿਤ ਕਰੋ, ਜਨਤਕ ਸੰਪਤੀ URL, ਆਕਾਰ ਅਤੇ ਹੈਸ਼ਾਂ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ, ਅਤੇ `docs/releases.json` ਵਿੱਚ ਅਸਲ ਪ੍ਰਕਾਸ਼ਨ ਮਿਤੀ ਨੂੰ ਰਿਕਾਰਡ ਕਰੋ।
6. ਡਾਉਨਲੋਡ ਪੰਨਿਆਂ ਅਤੇ ਅਨੁਵਾਦਾਂ ਨੂੰ ਅੱਪਡੇਟ ਕਰੋ, ਫਿਰ GitHub Desktop ਵਿੱਚ ਉਹਨਾਂ ਦੀਆਂ ਤਬਦੀਲੀਆਂ ਨੂੰ ਕਮਿਟ/ਪੁਸ਼ ਕਰੋ।

ਪ੍ਰਤੀ-ਪ੍ਰੋਜੈਕਟ ਟੈਗ ਲਿੰਕ ਸਾਂਝੇ ਕੀਤੇ `releases/latest` ਲਿੰਕ ਰਾਹੀਂ ਉਪਭੋਗਤਾਵਾਂ ਨੂੰ ਦੂਜੇ ਟੂਲ 'ਤੇ ਭੇਜਣ ਤੋਂ ਬਚਦੇ ਹਨ। GitHub ਦੇ ਆਟੋਮੈਟਿਕ **Source code** ਪੁਰਾਲੇਖਾਂ ਵਿੱਚ ਇਹ ਦਸਤਾਵੇਜ਼ੀ ਹੱਬ ਸ਼ਾਮਲ ਹੈ। ਐਪਲੀਕੇਸ਼ਨ ਸਰੋਤ ਨਿੱਜੀ ਰਹਿੰਦੇ ਹਨ। ਮੂਲ ਕੰਪੋਨੈਂਟ ਨੋਟਿਸ ਬਰਕਰਾਰ ਰਹਿੰਦੇ ਹਨ, ਅਤੇ ਇੱਕ ਰੀਲੀਜ਼ NVMFG ਦੇ ਦਸਤਾਵੇਜ਼ੀ NVIDIA SDK ਰਿਜ਼ਰਵ ਨੂੰ ਹੱਲ ਨਹੀਂ ਕਰਦੀ ਹੈ।


ਸਤੰਬਰ 18 ਦਾ ਅਪਡੇਟ ਤਿੰਨ ਨਵੇਂ ਟੈਗ ਤਿਆਰ ਕਰਦਾ ਹੈ; ਮੌਜੂਦਾ Profile Inspector ਰੀਲੀਜ਼ ਬਦਲਿਆ ਨਹੀਂ ਹੈ। ਸੰਪਤੀ ਦੇ ਨਾਮ, ਟੈਗਸ ਅਤੇ `SHA256SUMS.txt` ਐਪਲੀਕੇਸ਼ਨ ਅੱਪਡੇਟ ਜਾਂਚਾਂ ਲਈ ਸਟੀਕ ਰਹਿਣੇ ਚਾਹੀਦੇ ਹਨ। ਸਥਾਈ-ਰਿਲੀਜ਼ ਜਾਂਚਾਂ ਦਾ ਪਰਦਾਫਾਸ਼ ਕਰਨ ਲਈ ਪੂਰਵ-ਰਿਲੀਜ਼ ਫਲੈਗ ਤੋਂ ਬਿਨਾਂ ਆਮ ਰੀਲੀਜ਼ਾਂ ਨੂੰ ਪ੍ਰਕਾਸ਼ਿਤ ਕਰੋ; NVMFG ਪ੍ਰਯੋਗਾਤਮਕ ਰਹਿੰਦਾ ਹੈ।

<a id="integrity-and-storage"></a>
## ਇਕਸਾਰਤਾ ਅਤੇ ਸਟੋਰੇਜ

ਪ੍ਰਕਾਸ਼ਿਤ ਬਾਈਨਰੀ ਬਾਈਟਾਂ ਨੂੰ ਕਦੇ ਵੀ ਚੁੱਪਚਾਪ ਨਾ ਬਦਲੋ। ਨਵੇਂ ਹੈਸ਼ਾਂ ਦੇ ਨਾਲ ਇੱਕ ਨਵਾਂ ਸਪਸ਼ਟ ਸੰਸਕਰਣ ਜਾਂ ਇੰਸਟਾਲਰ ਸੰਸ਼ੋਧਨ ਦੀ ਵਰਤੋਂ ਕਰੋ। ਕਨੂੰਨੀ ਸਾਈਡਕਾਰਸ ਏਮਬੈਡਡ ਨੋਟਿਸਾਂ ਦੀ ਪੂਰਤੀ ਕਰਦੇ ਹਨ। NVDriverForge 0.1.4 ਪੋਰਟੇਬਲ 142,017,891 ਬਾਈਟ ਹੈ, GitHub ਦੀ ਆਮ 100 MiB ਗਿੱਟ-ਫਾਈਲ ਸੀਮਾ ਤੋਂ ਉੱਪਰ। ਰੀਲੀਜ਼ ਅਟੈਚਮੈਂਟ ਇਸ ਹੱਬ ਵਿੱਚ ਬਾਈਨਰੀ ਜਾਂ ਗਿੱਟ ਐਲਐਫਐਸ ਪਾਉਣ ਤੋਂ ਬਚਦੇ ਹਨ। [GitHub ਵੱਡੀ-ਫਾਈਲ ਮਾਰਗਦਰਸ਼ਨ](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)।

ਰਿਪੋਜ਼ਟਰੀ ਸੁਰੱਖਿਆ ਸੈਟਿੰਗਾਂ ਵਿੱਚ ਨਿੱਜੀ ਕਮਜ਼ੋਰੀ ਰਿਪੋਰਟਿੰਗ ਨੂੰ ਸਮਰੱਥ ਬਣਾਇਆ ਜਾਣਾ ਚਾਹੀਦਾ ਹੈ। ਉੱਥੇ ਸੰਵੇਦਨਸ਼ੀਲ ਰਿਪੋਰਟਾਂ ਨੂੰ ਨਿਰਦੇਸ਼ਿਤ ਕਰਨ ਤੋਂ ਪਹਿਲਾਂ ਇਸਦੀ ਉਪਲਬਧਤਾ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ; [SECURITY.md](../SECURITY.md) ਇੱਕ ਫਾਲਬੈਕ ਪ੍ਰਦਾਨ ਕਰਦਾ ਹੈ ਜੋ ਕਮਜ਼ੋਰੀ ਦੇ ਵੇਰਵਿਆਂ ਨੂੰ ਉਜਾਗਰ ਨਹੀਂ ਕਰਦਾ ਹੈ।
