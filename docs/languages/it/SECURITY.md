# Sicurezza

Questa politica copre i pacchetti applicativi NV Tools e questo hub di distribuzione. Il manutentore dà priorità ai report che riguardano l'ultima versione pubblicata di ciascuno strumento. I candidati preparati non sono una versione stabile supportata annunciata. Non viene promessa alcuna scadenza per la risposta o certificazione di sicurezza.

<a id="report-privately"></a>
## Segnalatelo in privato

Per vulnerabilità, comportamenti elevati non sicuri, modifiche distruttive involontarie o esposizione di dati sensibili, utilizzare la funzione **Sicurezza → Report a vulnerability** del repository **quando è abilitata**: [rapporto privato](https://github.com/Zendo-GIT/NV-Laboratory/security/advisories/new).

**Configurazione iniziale:** il manutentore deve abilitare la segnalazione privata delle vulnerabilità dopo aver creato il repository pubblico. Questo file non lo abilita e prima di allora non viene dichiarata l'esistenza di alcuna casella di posta o canale privato.

Se il pulsante non è disponibile, apri un problema pubblico contenente solo: "Ho bisogno di un canale di contatto privato per un rapporto sulla sicurezza riguardante [strumento/versione]". Non includere dettagli dell'exploit, credenziali, percorsi interessati, registri o allegati. Attendi che il manutentore fornisca un canale privato prima di condividerli.

Nel rapporto privato, includi strumento/versione e hash, versioni Windows/GPU/driver, impatto, riproduzione minima sicura e se è necessario il ripristino. Redigere segreti e dati personali; conservare i file di ripristino locali. Non caricare driver proprietari o DLL di giochi. Coordinare la divulgazione con il manutentore; una patch/release richiede una revisione e non è automatica.


[GitHub documentazione di reporting privato](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
