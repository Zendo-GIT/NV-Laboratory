<a id="security"></a>
# Безпека

Ця політика поширюється на пакети програм NV Tools і цей центр розподілу. Супроводжувач визначає пріоритетність звітів, що стосуються останньої опублікованої версії кожного інструменту. Підготовлені кандидати не є оголошеним підтримуваним стабільним випуском. Термін відповіді чи сертифікат безпеки не обіцяють.

<a id="report-privately"></a>
## Повідомте приватно

Для вразливостей, небезпечної підвищеної поведінки, ненавмисних деструктивних змін або розкриття конфіденційних даних використовуйте функцію **Безпека → Report a vulnerability** сховища, **якщо її ввімкнено**: [приватний звіт](https://github.com/Zendo-GIT/NV-Laboratory/security/advisories/new).

**Початкове налаштування:** супроводжувач повинен увімкнути приватне звітування про вразливості після створення загальнодоступного сховища. Цей файл не вмикає його, і до цього часу не стверджується, що поштова скринька чи приватний канал існували.

Якщо кнопка недоступна, відкрийте загальнодоступну проблему, яка містить лише: «Мені потрібен приватний контактний канал для звіту про безпеку щодо [інструмента/версії]». Не включайте відомості про експлойт, облікові дані, уражені шляхи, журнали чи вкладення. Зачекайте, поки супроводжувач надасть приватний канал, перш ніж ділитися ними.

У приватному звіті вкажіть інструмент/версію та хеш, версії Windows/GPU/драйвера, вплив, мінімальне безпечне відтворення та чи потрібне відновлення. Редагувати секрети та особисті дані; зберегти локальні файли відновлення. Не завантажуйте власний драйвер або DLL-файли ігор. Узгоджувати розкриття інформації з супроводжувачем; патч/реліз потребує перегляду й не виконується автоматично.


[GitHub приватна звітна документація](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
